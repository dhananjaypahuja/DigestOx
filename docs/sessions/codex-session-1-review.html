Findings for Claude

P1 · R1 Approval can be cleared or forged

src/customer_pulse/migrations/0001_initial.sql:196–211,334–346

The approved-content trigger only checks content updates while the old approval hash is present. An approved row can first become a draft with NULL approval fields, then have its content changed. Conversely, a draft may contain an approval hash, and the publish trigger checks that hash without checking status.

UPDATE digests SET status='draft', approved_sha256=NULL, approved_at=NULL
WHERE digest_id='dg_0001';
UPDATE digests SET content_md='changed after approval', content_sha256=:new_hash
WHERE digest_id='dg_0001';
-- Both succeed. A separate draft with matching approval fields also accepts
-- a publish_steps row with step='doc_pushed', status='done'.

Contract: DESIGN section 9 requires edits to create a new draft version and rejects publication of anything unapproved. Freeze approval history and approved content together; define legal status transitions, make draft/approval fields consistent, and require an approved publishing state in insert/update guards. Test downgrade-then-edit, forged draft, and positive retry/supersession paths.

P1 · R2 Later issue imports rewrite historical run facts

src/customer_pulse/migrations/0001_initial.sql:405–411,481–490

v_issue_latest selects the highest import globally. The run-scoped closure view joins it without a run-bound observation/input snapshot. A fixed run therefore changes when later issue state arrives.

Issue closes: 2026-09-30
Confirmed customer report: 2026-10-06
Run cutoff: 2026-10-08 → reported-after-closure count = 1
Add OPEN issue observation: 2026-10-09
Query the SAME run → count = 0

Contract: DESIGN sections 3 and 5 forbid later issue state changes influencing a digest. A live latest-issue view is useful, but cannot be the source of historical run facts. Bind runs to their evidence snapshot and derive issue state at the cutoff, preserving unknown reopen history explicitly. Do not simply reject exports imported later: an export may contain valid earlier facts. Test that a later observation cannot change an existing run and that close/reopen ambiguity is handled honestly. LLM replay cannot repair SQL fact drift.

P2 · R3 A merge cycle silently removes themes and facts

src/customer_pulse/migrations/0001_initial.sql:150–165,370–402

Only direct self-merges are rejected. A→B followed by B→A succeeds. The resolution CTE begins from roots, so the cycle has no resolved rows; assignments disappear through the inner join. Reproduced resolution rows: 2→0; fact rows: 1→0.

Reject cycles and either enforce the supported maximum chain depth or remove silent truncation at depth 64. Add two-node, longer-cycle, and over-depth tests, while retaining positive merge-chain coverage. This protects the stable-theme identity contract before merge/split commands are built.

P2 · R4 Publishing ownership proof is incomplete and mutable

src/customer_pulse/migrations/0001_initial.sql:320–346,513–518

A successful doc_pushed row accepts NULL document hash and team commit, yet becomes v_last_published_doc. Updating an older successful row's attempt count and updated_at also makes it appear newer than a later real push.

Require complete proof for successful pushes and preserve an immutable completion ordering, for example immutable success events distinct from mutable retry bookkeeping. Test missing proof and updating an older attempt after a newer completed push. This is needed for DESIGN section 9's ownership check, not a change to its approved sync-before-check publishing order.

P2 · R5 Expected operational errors escape JSON output

src/customer_pulse/cli.py:73–83

The CLI catches only PulseError. With a file at .pulse, init --json exits 1 with empty stdout and a FileExistsError (a traceback in a terminal invocation), instead of the promised structured error. Filesystem and SQLite operational failures need boundary translation to stable codes.

Add JSON-mode coverage for a non-directory state path, denied I/O, and corrupt/locked databases. Preserve actionable human output and do not hide unexpected programming errors behind a generic success-shaped result.

P2 · R6 Existing state directories bypass privacy protection

src/customer_pulse/cli.py:114–117

mkdir(mode=0o700, exist_ok=True) does not change an existing directory. With a pre-existing 0755 state directory, init succeeds and retains 0755; the new database is 0644 under umask 022. Other local users could read the evidence wherever parent-directory permissions permit access.

Enforce private database creation and validate directory privacy, handling existing databases and SQLite companion files consistently. Reject unsafe configurations or obtain consent rather than silently changing arbitrary user-selected directories. Test existing permissive directories and existing database files, not just newly created directories.

#!/usr/bin/env python3
"""Runnable reproductions for four Customer Pulse migration-0001 review findings.

Usage:
    python3 /private/tmp/customer_pulse_schema_repros.py [REPO_ROOT]

The script uses a fresh in-memory database for every case and executes the repository's
committed migration verbatim.  It does not write to the repository or to a database file.

Important cutoff distinction: ``v_issue_latest`` may reasonably be useful as a live/current
view.  The defect reproduced below is that the run-scoped
``v_run_reported_after_closure`` consumes that mutable live view, so adding an issue state
change after a run's cutoff changes the facts returned for that already-defined run.  This is
contrary to DESIGN.md's explicit promise that later issue state changes cannot influence a
digest.  LLM replay does not repair this: replay freezes model responses, while this flag is a
SQL-computed fact and the full rendered request itself depends on the SQL facts.
"""

from __future__ import annotations

import sqlite3
import sys
from pathlib import Path


REPO = Path(sys.argv[1]) if len(sys.argv) > 1 else Path("/Users/pahujad/Workbench/DigestOx")
MIGRATION = REPO / "src/customer_pulse/migrations/0001_initial.sql"

T0 = "2026-10-01T00:00:00.000000Z"
T1 = "2026-10-08T00:00:00.000000Z"
T2 = "2026-10-09T00:00:00.000000Z"
T3 = "2026-10-10T00:00:00.000000Z"
H_A = "a" * 64
H_B = "b" * 64
H_C = "c" * 64
H_D = "d" * 64


def database() -> sqlite3.Connection:
    if not MIGRATION.is_file():
        raise SystemExit(f"migration not found: {MIGRATION}")
    conn = sqlite3.connect(":memory:")
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")
    conn.executescript(MIGRATION.read_text(encoding="utf-8"))
    return conn


def add_run(conn: sqlite3.Connection, run_id: int = 1) -> None:
    conn.execute(
        """
        INSERT INTO runs (
            run_id, kind, mode, window_start, window_end, cutoff, timezone,
            started_at, status
        ) VALUES (?, 'digest', 'offline', ?, ?, ?, 'UTC', ?, 'succeeded')
        """,
        (run_id, T0, T1, T1, T1),
    )


def add_digest(
    conn: sqlite3.Connection,
    digest_id: str,
    content: str,
    content_hash: str,
    *,
    status: str = "approved",
    previous: str | None = None,
) -> None:
    approved_hash = content_hash if status == "approved" else None
    approved_at = T1 if approved_hash else None
    conn.execute(
        """
        INSERT INTO digests (
            digest_id, run_id, previous_digest_id, content_md, content_sha256,
            status, approved_sha256, approved_at, created_at
        ) VALUES (?, 1, ?, ?, ?, ?, ?, ?, ?)
        """,
        (
            digest_id,
            previous,
            content,
            content_hash,
            status,
            approved_hash,
            approved_at,
            T1,
        ),
    )


def approval_can_be_revoked_or_forged() -> None:
    conn = database()
    add_run(conn)

    add_digest(conn, "dg_0001", "approved content", H_A)
    conn.execute(
        """
        UPDATE digests
        SET status = 'draft', approved_sha256 = NULL, approved_at = NULL
        WHERE digest_id = 'dg_0001'
        """
    )
    conn.execute(
        """
        UPDATE digests
        SET content_md = 'changed after approval', content_sha256 = ?
        WHERE digest_id = 'dg_0001'
        """,
        (H_B,),
    )
    downgraded = conn.execute(
        "SELECT status, content_md, approved_sha256 FROM digests WHERE digest_id = 'dg_0001'"
    ).fetchone()
    assert tuple(downgraded) == ("draft", "changed after approval", None)

    # The CHECK is only one-way, so a draft is allowed to carry approval fields.
    conn.execute(
        """
        INSERT INTO digests (
            digest_id, run_id, content_md, content_sha256, status,
            approved_sha256, approved_at, created_at
        ) VALUES ('dg_0002', 1, 'forged draft', ?, 'draft', ?, ?, ?)
        """,
        (H_C, H_C, T1, T1),
    )
    conn.execute(
        """
        INSERT INTO publish_steps (
            digest_id, step, status, approved_sha256, updated_at
        ) VALUES ('dg_0002', 'doc_pushed', 'done', ?, ?)
        """,
        (H_C, T1),
    )
    forged = conn.execute(
        """
        SELECT d.status, p.step, p.status
        FROM digests AS d JOIN publish_steps AS p USING (digest_id)
        WHERE d.digest_id = 'dg_0002'
        """
    ).fetchone()
    assert tuple(forged) == ("draft", "doc_pushed", "done")
    print(
        "[P1 approval] approved digest became mutable:",
        tuple(downgraded),
        "; unapproved draft accepted publish:",
        tuple(forged),
    )
    conn.close()

def merge_cycle_erases_theme_facts() -> None:
    conn = database()
    add_run(conn)
    conn.executemany(
        "INSERT INTO themes (theme_id, title, created_at) VALUES (?, ?, ?)",
        [("th_0001", "A", T0), ("th_0002", "B", T0)],
    )
    conn.execute(
        """
        INSERT INTO imports (import_id, source, file_name, content_sha256, imported_at)
        VALUES (1, 'slack', 'slack.json', ?, ?)
        """,
        (H_A, T0),
    )
    conn.execute(
        """
        INSERT INTO signals (
            signal_id, source, source_key, occurred_at, text_redacted, raw_sha256,
            first_import_id, last_import_id
        ) VALUES (
            1, 'slack', 'C1:1', '2026-10-06T00:00:00.000000Z', 'signal', ?, 1, 1
        )
        """,
        (H_B,),
    )
    conn.execute(
        """
        INSERT INTO assignments (
            assignment_id, signal_id, theme_id, set_by, run_id, created_at

def ownership_anchor_is_incomplete_and_mutable() -> None:
    conn = database()
    add_run(conn)
    add_digest(conn, "dg_0001", "one", H_A)
    add_digest(conn, "dg_0002", "two", H_B, previous="dg_0001")

    conn.execute(
        """
        INSERT INTO publish_steps (
            digest_id, step, status, approved_sha256, updated_at
        ) VALUES ('dg_0001', 'doc_pushed', 'done', ?, ?)
        """,
        (H_A, T1),
    )
    incomplete = conn.execute(
        "SELECT digest_id, doc_sha256, team_commit FROM v_last_published_doc"
    ).fetchone()
    assert tuple(incomplete) == ("dg_0001", None, None)

    # Fill the missing proof, then record a later successful push for dg_0002.
    conn.execute(
        """
        UPDATE publish_steps
        SET doc_sha256 = ?, team_commit = ?
        WHERE digest_id = 'dg_0001' AND step = 'doc_pushed'
        """,
        ("1" * 64, "1" * 40),
    )
    conn.execute(
        """
        INSERT INTO publish_steps (
            digest_id, step, status, approved_sha256, doc_sha256, team_commit, updated_at
        ) VALUES ('dg_0002', 'doc_pushed', 'done', ?, ?, ?, ?)
        """,
        (H_B, "2" * 64, "2" * 40, T2),
    )
    correct_latest = conn.execute("SELECT digest_id FROM v_last_published_doc").fetchone()[0]
    assert correct_latest == "dg_0002"

    # A harmless-looking update of the older success rewrites which push the view calls last.
    conn.execute(

        UPDATE publish_steps

        (T3,),
    )
    rewritten_latest = conn.execute("SELECT digest_id FROM v_last_published_doc").fetchone()[0]
    assert rewritten_latest == "dg_0001"
    print(
        "[P2 ownership] accepted incomplete anchor:",
        tuple(incomplete),
        "; latest changed after stale-row update:",
        f"{correct_latest} -> {rewritten_latest}",
    )
    conn.close()
